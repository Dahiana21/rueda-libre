Comprobación de herencia de CSS
Propiedad que se hereda: font-family
Se revisó la regla body, donde se definió la fuente de texto mediante font-family: var(--fuente-texto). Esta propiedad se hereda 
en los párrafos, permitiendo que utilicen Open Sans sin necesidad de declarar nuevamente la fuente en cada elemento.

Propiedad que no se hereda: background-color
Se analizó la propiedad background-color del párrafo y del cuerpo del documento. 
El body tiene asignado el color Crema mediante var(--crema), mientras que el párrafo conserva un fondo transparente. 
Esto demuestra que el color de fondo no se hereda automáticamente.

Verificación de tipografías

Conflicto de especificidad
Se analizaron las reglas CSS #menu a y .activo utilizando la herramienta DevTools de Google Chrome.
El selector #menu a tiene una especificidad de (1, 0, 1) porque contiene un identificador y un elemento HTML.
El selector .activo tiene una especificidad de (0, 1, 0) porque contiene únicamente una clase.
Se identificó que #menu a tiene mayor especificidad y, por lo tanto, su propiedad color prevalece sobre la propiedad color de .activo, 
aunque esta última esté declarada después. La clase .activo sí se aplica, pero su declaración de color queda sobrescrita. 
La propiedad font-weight puede mantenerse porque no entra en conflicto con la otra regla.

Para solucionar el conflicto entre los selectores #menu a y .activo, se utilizó el selector #menu a.activo, cuya especificidad es (1, 1, 1).
Este selector tiene mayor prioridad que #menu a, con especificidad (1, 0, 1), y que .activo, con especificidad (0, 1, 0).También se aplicó 
un fondo Naranja Pedal con texto Azul Noche al enlace activo para identificar visualmente la página actual y mantener un contraste accesible.

5. Ventajas y desventajas

 Ventajas

- Bootstrap facilita la creación de diseños responsive.
- Permite reutilizar clases de distribución y espaciado.
- Reduce la necesidad de programar algunas media queries.
- Facilita mantener una estructura consistente entre páginas.
- Agiliza la organización de tarjetas, tablas y formularios.

Desventajas

- Sus colores predeterminados no siempre coinciden con la identidad visual.
- Puede ser necesario sobrescribir algunos estilos mediante CSS propio.
- Las etiquetas HTML pueden contener numerosas clases.
- El desarrollador debe conocer la grilla y los breakpoints de Bootstrap.


7. Conclusión
La migración de Rueda Libre a Bootstrap permitió simplificar la organización responsive de las páginas, especialmente 
en las secciones que anteriormente dependían de distribuciones personalizadas con CSS Grid y Flexbox.

Bootstrap ofreció ventajas para distribuir tarjetas, formularios y tablas utilizando clases reutilizables. 
Sin embargo, fue necesario conservar CSS propio para mantener la identidad visual definida por el manual de marca.

Se concluye que combinar Bootstrap para las distribuciones con CSS personalizado para la identidad visual es u
na alternativa adecuada para Rueda Libre, ya que facilita el mantenimiento y permite conservar el diseño corporativo.

Para determinar con precisión cuánto trabajo se redujo, es necesario completar las mediciones reales de 
líneas de código y tiempo invertido.

Se identificó como posible causa que el cambio del nombre de la carpeta, realizado localmente, todavía no se había enviado a GitHub.


Dificultades encontradas

La primera dificultad consistió en intentar validar una página local mediante su dirección de Live Server, lo cual produjo el mensaje `Forbidden host`.

Otra dificultad fue identificar y corregir los errores reportados por W3C relacionados con espacios en las rutas de las imágenes.

También se presentaron errores en los atributos `autocomplete` de los formularios y en la configuración ARIA del modal de políticas.

Adicionalmente, se detectó un problema con el nombre de la carpeta Bootstrap, ya que la estructura local y la publicada en GitHub todavía podían ser diferentes.

Finalmente, se requirió revisar cuidadosamente las dimensiones de las tarjetas y comprender el funcionamiento de la pestaña Computed de DevTools.

14. Soluciones aplicadas

Para validar las páginas locales se utilizó la opción de carga de archivos del validador W3C.

Se corrigieron las rutas de imágenes mediante la codificación de espacios como %20, evitando modificar innecesariamente los nombres de los archivos.

En los campos de celular se utilizó autocomplete="tel" para eliminar los errores reportados.

En el modal de políticas se incorporó un rol ARIA compatible con su funcionamiento.

Para comprobar la distribución de los planes se utilizó Chrome DevTools y se registraron las medidas reales de los elementos.

Se corrigió el nombre de la carpeta boostrap a bootstrap para establecer una estructura coherente con los enlaces internos.

16. Resultados obtenidos

Se avanzó en la preparación del ecosistema Rueda Libre para su entrega final.

Se identificaron y corrigieron errores de estructura HTML en las páginas revisadas.

Se comprobó el uso de estilos responsive y colores de modo oscuro en la landing.

Se verificó mediante Chrome DevTools que las tres tarjetas de planes mantienen dimensiones exteriores equivalentes.

Se creó el archivo README.md y se preparó la información necesaria para documentar el proyecto.
